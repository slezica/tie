# CLI reorg: current tile, `--tile`, entropic ids, `set`, aliases

Session record. Goals from the user; `docs/CLI.md` is the guide to update when settled.

# Goals

1. Commands act on the current tile by default (the process container, by lineage: already so via `caller`).
2. Every tile-affecting command takes `--tile <id>` for another tile (replaces positional `[id]`).
3. Tile ids entropic: never repeat, not even across runs. Scripts can't hit a reintroduced id.
4. Top-level commands are verbs: `title` + `icon` → `set --title T --icon E`.
5. Single-letter aliases: `l a r c m f s p` (first letter, all unique today).
6. `get` postponed: needs design (scope: tile, tab, board?).

# Research

## 1. Id format

- Today: `t${++seq}` (`state.ts` `newId`), `s${++spaceSeq}`. Restart → `t1` again.
- Where ids live: `S.tiles` key, `el.dataset.id`, `TIE_TILE` env (pty → tile map in main), socket params, `tie list`. No format assumption in code (grepped `^t`, `t\d`); 4 scenarios regex the log for `t\d+` (`sec-focus`, `sec-content-escape`, `sec-html`): update.
- Human cost: ids are typed (`tie move t7 --tab 2`, `--at`, `--swap`). Random ids must stay short and unambiguous.
- Proposal: prefix + 6 chars, lowercase base32 without `0 1 l o` (28 symbols ≈ 29 bits per 6 chars). `t-k3x9qa`? Lean: `tk3x9qa`-style is noisier; `t7f2kqa` without a dash is fine and keeps `t` as kind marker.
- Collision: ~500M space; even 1000 tiles over the life of a script → ~0.0001% chance of any two equal. Plus a live check against `S.tiles` on generation (free).
- Digits-only never: a prefix letter keeps `--tab <position>` unambiguous.

## 2. Tab ids

- `--tab` takes id (`s1`) or 1-based position; positions are the human form already.
- Same hazard for scripts (`tie move --tab s2` after restart). Lean: same scheme, prefix `s`, for consistency. Cost: nil (ids are opaque in code).

## 3. `set` shape

- A. Flags: `tie set --title "migrating db" --icon 🛠️`. Pro: one call, same vocabulary as `add --title`. Con: multi-word title needs quotes (today `tie title migrating db` joins).
- B. Subcommand: `tie set title migrating db`. Pro: unquoted words, mirrors a future `tie get title`. Con: two calls for two props; `tie set title` vs `--title` on `add`: two spellings.
- Lean: A. Quoting is normal CLI hygiene; agents quote anyway.

## 4. Tab / tile naming

- Collision matters only for single-letter option shorts. Already hopeless there: `--float/--focus`, `--side/--swap/--shelved`, `--tab/--tile/--title`. Lean: no option shorts at all; letters only for commands.
- `board` for tab: taken. Board = slot area, vs floats and shelf (`not on board: <id>`, `list --json` `board`). A tab = board + floats + shelf. Overloading muddies errors + docs.
- `space` for tab: internal name already (`Space`, ids `s1`, `TABS.md`). Cost: UI says tab, CLI says space.
- Lean: keep `--tab` + `--tile`, spelled out. Revisit with the `block` rename if it comes.

# Settled

- `set`: flags, one call sets several fields. `set --title T --icon E`. Socket: one `set {id, title?, icon?}` method replaces `title` / `icon`.
- Clearing: `""` restores the default, general rule for properties.
- `--tile <id>` on every tile command (`close`, `move`, `focus`, `ping`, `set`); positional `[id]` gone. Default: the caller.
- No current tile (external caller, no `--tile`): `no current tile: use --tile <id>`.
- Ids: prefix + 6 chars, lowercase base32 minus `0 1 l o`; tiles `t`, tabs `s`. Live uniqueness check on generation.
- Names stay `tab` / `tile`. No single-letter option flags; single-letter aliases for commands: `l a r c m f s p`.
- `add --icon` for symmetry with `set`.
