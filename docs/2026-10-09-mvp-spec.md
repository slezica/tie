# MVP Spec

Outcome of brainstorming 2026-10-08/09. Goal: feel the core interactions (splits, floating, shelf) with terminal tiles, scriptable by agents via CLI.

## Core Idea

Single full-screen Electron window with one **space**: a **board** of tiles (slotted tree + floating) and a **shelf** column on the right holding temporarily parked tiles. All management by mouse. A `tie` CLI lets shells and agents inside Tie control tiles.

## Scope

- In: terminal tiles, slot tree splits, floating, collapse, zoom, shelf, `tie` CLI, `tie-dev` harness.
- Out: tabs/multiple spaces, browser tiles, keyboard tile management, persistence, MCP, agent HTML tiles, auth.

## Rationale (key decisions)

- **Minimality**: UI-centric, renderer owns state. Daemon-client design shelved, see `2026-10-09-daemon-client-architecture.md`.
- **Mouse first**: validate mouse interactions before adding keyboard.
- **CLI over MCP**: agents use shells well; no MCP config; humans can script it.
- **No terminal send/read via CLI**: terminals may run elevated programs, scrollback may hold secrets. Agents pipe their own output.
- **Visuals imitate Wave Terminal**: cheap starter to feel interactions before settling style. Accent = light blue instead of Wave's green.

## Architecture

- **Main process**
  - Window, single-instance lock (per `TIE_INSTANCE`).
  - pty host (`node-pty`), IPC to renderer.
  - Unix socket server (JSON-RPC, newline-delimited) → forwards calls to renderer → returns results.
- **Renderer**
  - Owns all state (board tree, floating list, shelf, tiles). Sync, plain objects + `render()`.
  - All tiles absolutely positioned in one container; rects computed from state. Tiles never re-parented → xterm never remounts.
- **CLI `tie`**: Node script, connects to `$TIE_SOCKET`.
- **Env injected into shells**: `TIE_SOCKET`, `TIE_TILE`, `PATH` prepended with `bin/`.
- **Terms**: space = board + shelf (+ cwd). Driver = socket interface mapping commands to internal methods.

## Board

- **Slot tree**: n-ary splits, normalized (no single-child splits; same-direction nested splits merge).
- **Sizes**: fractions of parent; min size px.
- **Drop zones**: target tile split by diagonals into 4 triangles; nearest edge wins. New tile takes half the target's space.
- **Drop preview**: highlight of resulting shape during drag.
- **Floating**: fixed px size + position, outside layout, clamped into board on shrink. Always above slotted; focus raises.
- **Collapse**: tile shrinks to title bar, siblings take space.
  - In vertical (top/bottom) split: horizontal bar.
  - In horizontal (side-by-side) split: vertical strip, title rotated 90°.
  - Click to expand. No hover reveal.
- **Zoom**: temporary maximize of one tile over board.
- **Focus**: click focuses (raises if floating). Non-empty board always has active tile. After close: MRU.
- **Empty board**: allowed.

## Shelf

- Per space. Fixed narrow column on the right, always visible.
- **Templates** at top, above separator: tile kinds (MVP: terminal). Drag onto board spawns new tile.
- **Items**: fixed-height rows, icon + title, arrival order, drag to reorder.
  - Title from terminal title escape sequence, fallback foreground process name. Icon from program → emoji table.
  - Overridable via right-click menu (custom title, emoji icon).
  - Activity indicator: new-output dot, exit status.
- **Reveal on hover**: non-interactive preview, hides on mouse leave.
  - Max 30% board width × 50% board height.
  - `>` peak pointing at the item; rect clamped into board, peak stays aligned.
- **Pin**: click item → reveal stays open, tile active and interactive. Click item again or outside → unpin.
- **pty size**: shelved terminal always at reveal size (no resize churn on hover).
- **Shelve**: drag tile onto shelf (only way). Tile leaves layout, siblings reflow, focus MRU.
- **Unshelve**: drag item onto board, same mechanic as moving tiles.

## Mouse Map

- Title bar drag: move with drop preview. Shift held at drop → float. Drop on shelf → shelve.
- Title bar buttons: collapse, zoom, close. Double-click title → zoom.
- Right-click title (board or shelf): HTML context menu → rename, set emoji icon.
- Slotted: drag shared border → resize both neighbors. Floating: drag edges/corners.
- During any drag: `pointer-events: none` on tile content (drag shield).
- Keyboard: cmd+c/v in terminal, cmd+q. Nothing else.

## CLI `tie`

- `<id>` defaults to `$TIE_TILE`. Plain output; `--json` flag.
- `tie list`: id, kind, title, state (slotted|floating|shelved|collapsed), rect.
- `tie open terminal [--cmd C] [--cwd D] [--title T] [--at ID --side l|r|t|b | --float | --shelved]` → prints new id.
- `tie close <id>`
- `tie move <id> (--at ID --side l|r|t|b | --float | --shelve)`
- `tie focus <id>`
- `tie title <id> <text>`, `tie icon <id> <emoji>`
- Later: `tie open browser`, `tie events`.

## Harness `tie-dev`

- `tie-dev run | build | test --unit | test --e2e`. Vitest for pure layout logic.
- `tie-dev layout`: ASCII render of board from `tie list --json`.
- `tie-dev screenshot`: capture current state via debugging port.
- `tie-dev drive <scenario> | -` (stdin): Playwright. Fresh instance by default, `--attach` to live app.
  - Scenarios: modules exporting `async (ctx)`. ctx = page, tie CLI wrapper, `shot(name)`.
  - Helpers: composable async fns (`dragTitle`, `hoverShelf`, `pin`, ...).
  - Screenshots to `tmp/shots/<scenario>/<n>-<name>.png`.
- `TIE_INSTANCE`: separate socket, lock, debug port per instance.
- `TIE_DEBUG=layout,shelf,pty`: tagged logs to file.
- Dev builds expose debugging port; never release builds.

## Visuals (Wave imitation)

- Near-black background, small gaps between tiles, rounded tiles.
- Title bar: icon + bold title left; action icons right.
- Active tile: accent border, light blue.
- Shelf styled like Wave's right widget bar (icon + small label).

## Implementation Plan

1. **Scaffold**: electron-vite + TS, pinned Electron, `node-pty` rebuild, `bin/tie-dev` (run, build, test).
2. **Terminal tile**: xterm.js + pty IPC, single tile filling board, env injection.
3. **Board**: slot tree model + unit tests, rect computation, render, border resize.
4. **Socket + CLI**: JSON-RPC socket in main, `tie` CLI, `tie-dev layout`. Enables scripted setup.
5. **Harness**: debugging port, `tie-dev screenshot`, `tie-dev drive` + helpers.
6. **Drag & drop**: title bar drag, triangle drop zones, preview, shift → float.
7. **Floating, collapse, zoom, focus/MRU**.
8. **Shelf**: templates, items, reveal, pin, activity, reorder, context menu.
9. **Polish**: Wave-like styling pass, scenarios for each feature.

Commit per step. Verify each phase with screenshots/scenarios.

## Concerns

- `<webview>` is discouraged API (browser tiles, post-MVP).
- Auth: socket open to any local process of the user. Fine for MVP.
- Feel (drag thresholds, previews) needs tuning rounds; spec can't settle it.
